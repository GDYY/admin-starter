# 巡检执行页 · 开发指南

> 这是系统里**唯一有真正业务价值**的页面。设备台账那种 CRUD 谁都会写，但「按点检标准动态生成表单 + 自动判定异常 + 主从表提交」这一套，是能写进简历的东西。

---

## 一、这页在系统里的位置

```
巡检计划（定义：哪台设备、多久一次、谁负责）
        ↓
【本页】巡检执行：系统按计划列出今日任务 → 巡检员逐项点检 → 提交
        ↓
巡检记录（主表）+ 记录明细（从表）+ 异常记录
```

**它不是 CRUD，是「录入 + 判定 + 汇总」。** 少了它，整个系统就只是个设备清单。

**为什么用抽屉（`el-drawer`）而不是独立页面？**

- 只有一条路由，不用处理路由传参和返回刷新
- 关闭抽屉直接刷新列表，逻辑最顺
- 用 `size="45%"` 控制宽度，内容够放

> 想做成独立页面也行，但**先把抽屉版本跑通**，别一上来就挑战难的。

## 三、数据结构（先把类型定下来，再写 UI）

新建 `src/types/inspect.ts`：

```ts
/** 点检类型：1=正常/异常  2=数值录入  3=文字描述 */
export type CheckType = 1 | 2 | 3

/** 点检项（= 一条点检标准） */
export interface InspectItem {
  id: number
  itemName: string
  category: string
  checkType: CheckType
  unit: string
  minValue: number | null
  maxValue: number | null
  standard: string
  sort: number
  status: number
}

/** 今日待巡检任务（= 一条巡检计划 + 设备信息 + 今日状态） */
export interface InspectTask {
  id: number
  planName: string
  deviceId: number
  deviceCode: string
  deviceName: string
  category: string
  location: string
  executor: string
  frequency: number
  lastInspectTime: string | null
  finished: boolean
}

/** 提交给后端的结构：主表 + 明细 */
export interface InspectSubmitPayload {
  planId: number
  deviceId: number
  inspectTime: string
  remark: string
  details: {
    itemId: number
    itemName: string
    checkValue: string
    isAbnormal: 0 | 1
    remark: string
  }[]
}
```

### ⭐ 最关键的一步：页面表单要「包一层」

**不要把 `InspectItem[]` 直接拿来做 v-model。** 后端返回的是「标准」，用户填的是「结果」——它们是两种东西，混在一起就是灾难（改一处污染全局、关掉抽屉数据还在）。

在页面里再包一层：

```ts
/** 表单行 = 点检标准 + 用户填的值 */
interface FormRow {
  item: InspectItem  // 标准，只读
  value: string      // 用户填的值，可写
  remark: string     // 异常描述
}

const rows = ref<FormRow[]>([])
```

这个「**数据（后端给的）和状态（用户输的）分开**」的思路，是这一页最值钱的知识点。

## 四、交互流程

```
1. 进页面 → 加载今日任务列表
2. 点「执行」→ 打开抽屉
3. 抽屉打开时：
     ① 查这台设备今天巡检过没（防重复）
     ② 按设备的 category 拉取对应的点检项
     ③ 点检项按 sort 排序，转成 FormRow[]
4. 巡检员逐项录入（三种控件）
5. 实时统计：已填 X 项 / 异常 Y 项
6. 点「提交」→ 先校验 → 组装 payload → 调接口
7. 成功 → 关抽屉 → 刷新列表（该任务变成「已完成」）
```

## 五、四个技术难点与解法

### 难点 1：按类型动态渲染不同的录入控件

用 `v-if / v-else-if / v-else` 三分支：

```vue
<div v-for="(row, index) in rows" :key="row.item.id" class="row">
  <div class="row-title">
    {{ index + 1 }}. {{ row.item.itemName }}
  </div>

  <div class="row-control">
    <!-- 类型 1：正常 / 异常 二选一 -->
    <el-radio-group v-if="row.item.checkType === 1" v-model="row.value">
      <el-radio value="正常">正常</el-radio>
      <el-radio value="异常">异常</el-radio>
    </el-radio-group>

    <!-- 类型 2：数值 + 单位 -->
    <el-input
      v-else-if="row.item.checkType === 2"
      v-model="row.value"
      placeholder="请输入"
      style="width: 180px"
    >
      <template #append>{{ row.item.unit }}</template>
    </el-input>

    <!-- 类型 3：文字描述 -->
    <el-input v-else v-model="row.value" placeholder="请描述检查结果" />
  </div>

  <div class="row-standard">标准：{{ row.item.standard }}</div>

  <!-- 异常时才出现的备注框 -->
  <el-input
    v-if="isAbnormal(row)"
    v-model="row.remark"
    type="textarea"
    :rows="2"
    placeholder="请描述异常情况（必填）"
    class="row-remark"
  />
</div>
```

> 💡 注意 `el-radio` 在新版 Element Plus 里用 `value` 而不是 `label` 绑定值。如果你的版本报错，换回 `label` 试试。

### 难点 2：数值超范围自动判异常

**不要用 watch 去同步一个 `isAbnormal` 字段**——那样容易出现「值和判定不一致」的 bug。

**用纯函数实时算**，最简单也最可靠：

```ts
function isAbnormal(row: FormRow): boolean {
  const { checkType, minValue, maxValue } = row.item

  // 类型 1：用户自己选的
  if (checkType === 1) return row.value === '异常'

  // 类型 2：数值超范围
  if (checkType === 2) {
    if (row.value === '' || row.value === null) return false
    const n = Number(row.value)
    if (Number.isNaN(n)) return false
    if (minValue !== null && n < minValue) return true
    if (maxValue !== null && n > maxValue) return true
    return false
  }

  // 类型 3：文字没法自动判定
  return false
}
```

然后统计就能实时跟上了：

```ts
const filledCount = computed(
  () => rows.value.filter((r) => r.value !== '' && r.value !== null).length,
)
const abnormalCount = computed(() => rows.value.filter(isAbnormal).length)
```

> 模板里 `isAbnormal(row)` 会被反复调用——`rows` 只有几到几十条，性能完全不用担心。

### 难点 3：提交前校验

**不要用 `el-form` 的 rules 管动态表单**（prop 要拼成 `details.0.value` 这种，很容易踩坑）。

**手写校验**，返回错误信息字符串：

```ts
function validate(): string | null {
  if (rows.value.length === 0) return '没有可巡检的点检项'

  for (const row of rows.value) {
    if (row.value === '' || row.value === null || row.value === undefined) {
      return `「${row.item.itemName}」还没有填写`
    }
    if (isAbnormal(row) && !row.remark.trim()) {
      return `「${row.item.itemName}」判定为异常，请填写异常描述`
    }
  }
  return null
}

async function handleSubmit() {
  const err = validate()
  if (err) {
    ElMessage.warning(err)
    return
  }
  // ...
}
```

**返回字符串而不是直接弹窗**，好处是这个函数可以单独测试，也方便复用。

### 难点 4：组装提交数据

```ts
const payload: InspectSubmitPayload = {
  planId: task.id,
  deviceId: task.deviceId,
  inspectTime: new Date().toLocaleString('zh-CN', { hour12: false }),
  remark: formRemark.value,
  details: rows.value.map((row) => ({
    itemId: row.item.id,
    itemName: row.item.itemName, // 冗余存名字：以后标准改名，历史记录仍显示当时的名字
    checkValue: String(row.value),
    isAbnormal: isAbnormal(row) ? 1 : 0,
    remark: row.remark,
  })),
}
```

## 六、API 层要加什么

新建 `src/api/inspect.ts`（写法照抄 `src/api/device.ts`）：

| 函数 | 说明 |
|---|---|
| `getTodayTasks(params)` | 今日待巡检任务列表 |
| `getInspectItems(category)` | 按设备类型取点检项（**按 sort 排序后返回**） |
| `getTodayRecord(deviceId)` | 查这台设备今天巡检过没（防重复提交） |
| `submitInspectRecord(payload)` | 提交，写主表 + 明细 |
| `getInspectRecords(params)` | 巡检记录查询（下一个页面用） |

同时新建 `src/mock/inspectDb.ts` 造假数据：

- `inspectItems`：给「电机 / 水泵 / 风机 / 配电柜 / 空压机 / 输送带」每个类型配 4–6 条点检项，**三种 checkType 都要有**
- 电机示例：
  - 油位检查（类型1，标准：油位在上下标线之间）
  - 运行温度（类型2，单位 ℃，正常范围 0–70）
  - 运行电流（类型2，单位 A，正常范围 0–15）
  - 轴承异响（类型1，标准：无异响）
  - 外观检查（类型3，标准：无明显破损、渗漏）

> ⚠️ 假数据里**三种类型都要覆盖**，否则你测不出动态渲染的 bug。

## 七、分 6 步实现（每一步都能独立跑起来）

| 步骤 | 做什么 | 预计 | 完成后 commit |
|---|---|---|---|
| **1** | 任务列表页（纯表格，点「执行」先弹个 `ElMessage`） | 半天 | `feat(inspect): 巡检任务列表` |
| **2** | 抽屉打开 → 拉点检项 → **静态展示**出来（先不做录入控件） | 半天 | `feat(inspect): 抽屉加载点检项` |
| **3** | 加三种录入控件（难点 1） | 半天 | `feat(inspect): 动态录入控件` |
| **4** | 加异常判定 + 红色高亮 + 底部实时统计（难点 2） | 半天 | `feat(inspect): 异常自动判定` |
| **5** | 加校验 + 组装数据 + 提交（难点 3、4） | 半天 | `feat(inspect): 巡检结果提交` |
| **6** | 收尾：提交后刷新列表、防重复、已完成的只能「查看」 | 1 小时 | `feat(inspect): 重复巡检校验` |

**每步都 commit** —— 就算第 5 步卡住，你也有 4 个可回退的版本，而且绿色格子一天不落。

## 八、7 个容易踩的坑

1. **别直接用后端对象做 v-model** —— 必须包一层 `FormRow`，否则污染源数据。
2. **`el-input` 拿到的一律是字符串** —— 数值要用 `Number()` 转；而且 `Number('')` 是 `0`，**必须单独判断空字符串**。
3. **抽屉关闭时要清空 `rows`** —— 否则下次打开还是上次的数据。
4. **点检项要按 `sort` 排序**再渲染 —— 顺序乱了现场没法用。
5. **同一设备同一天重复巡检** —— 要么禁止提交并提示，要么明确标注「补录」。
6. **提交按钮要 `loading`** —— 防止连点提交两次，产生两条记录。
7. **`el-drawer` 里内容超长要有滚动** —— 给 `body` 加 `overflow-y: auto`，否则提交按钮会被顶出屏幕。

## 九、验收标准

做完之后，自己跑一遍，满足以下全部就算过关：

- [ ] 进页面能看到今日任务列表，已完成的显示「查看」
- [ ] 点「执行」抽屉滑出，标题显示设备名和编号
- [ ] 点检项按顺序展示，三种类型渲染成三种控件
- [ ] 温度填 `80`（超过 70）时，立刻标红显示「异常」，并自动出现备注框
- [ ] 有项目没填就点提交，提示「「某某项」还没有填写」
- [ ] 异常项没写备注就点提交，提示「请填写异常描述」
- [ ] 全部填好提交，提示成功、抽屉关闭、列表刷新、该任务变成「已完成」
- [ ] 再点同一台设备的「执行」，提示今天已经巡检过
- [ ] `pnpm run type-check` 零错误
- [ ] 至少 6 次 commit，且都推到了 GitHub
